# 构建、安装与发布

> 这份文档是给**要改代码或要发版**的人看的。只想装来用，回 [README](../README.md) 就够了。
> 所有命令都在仓库根目录执行。

## 0. 环境

| 项 | 要求 |
|---|---|
| macOS | 13 Ventura 或更新（`MACOS_MIN`，与 `Package.swift`、App target 一致） |
| 架构 | Apple Silicon（只出 arm64；vendored cmark 用 `-mcpu=apple-m1` 编的） |
| Xcode | 完整 Xcode，**不能只有 CommandLineTools** |
| Python | 3.10+（`gen_project.py` 用了 `str | None`） |

两个本机踩过的先决条件：

```bash
sudo xcode-select -s /Applications/Xcode.app   # 指向 CommandLineTools 时能编，但打不出 .appex
```

`swift build` 一律加 `--disable-sandbox`，否则 `sandbox-exec: sandbox_apply: Operation not permitted`。

## 1. 生成 / 更新 Xcode 工程

`project.pbxproj` 是**脚本生成的**（手写容易漏 UUID 引用）。**加了源码文件就重跑一次**：

```bash
python3 scripts/gen_project.py
```

## 2. 构建

```bash
xcodebuild -project Spacedown.xcodeproj -scheme Spacedown -configuration Release \
           -derivedDataPath ~/Library/Caches/Spacedown/DerivedData build
```

产物：`~/Library/Caches/Spacedown/DerivedData/Build/Products/Release/Spacedown.app`

> 构建目录刻意放在 `~/Library/Caches`：Spotlight 不索引那里。放仓库内或
> `~/Library/Developer` 会被索引，搜「Spacedown」时同时命中已安装的和构建产物，
> 看起来像「卸载没生效」。

## 3. 安装并让系统重新发现扩展

```bash
killall Spacedown                     # 先退出
rm -rf /Applications/Spacedown.app    # 再替换
cp -R ~/Library/Caches/Spacedown/DerivedData/Build/Products/Release/Spacedown.app /Applications/

LSR=/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister
"$LSR" -f /Applications/Spacedown.app
pluginkit -a /Applications/Spacedown.app/Contents/PlugIns/QuickLookPreview.appex
qlmanage -r
```

然后**让 App 自己**跑一次接管（菜单「显示 → 接管 Markdown 空格预览」），
因为它要做的四步里有两步在沙箱外才允许。

⚠️ **绝对不要**对构建目录那份执行 `lsregister -u`。`-u` 按 **bundle ID** 注销，
两份副本同 ID，会把 `/Applications` 那条一起抹掉，空格预览当场中断
（2026-11-19 踩过）。真要清构建副本的登记，用 App 菜单重新接管一次即可。

⚠️ 注销/重登记之后 **pkd 要几十秒才重新发现**（日志里先出现
`LaunchServices observer: Uninstalled plugins`）。这段时间按空格用的是别家扩展，
**别在这几十秒里下结论**。

## 接管空格预览的四步选举

macOS 允许同一文件类型被多个 Quick Look 扩展认领，**由系统挑一个**。本机上 WPS 的
`WPSQuickLook.appex` 认领了同样 8 个 markdown 类型（含 `net.daringfireball.markdown`），
两个都注册时系统实测挑了 WPS。

沙箱里的进程不能调 `pluginkit`（TCC 拦死，`dangerouslyDisableSandbox` 也救不了），
所以选举交给非沙箱的主 App。`Spacedown/QuickLook/QuickLookClaim.swift` 做四步：

1. `lsregister -f /Applications/Spacedown.app` —— 重新登记 App 与内嵌扩展
2. `pluginkit -a …/QuickLookPreview.appex` —— 登记扩展
3. `pluginkit -e use -i cn.29dev.Spacedown.QuickLookPreview`
   \+ `pluginkit -e ignore -i com.kingsoft.wpsoffice.mac.WPSQuickLook`（关掉已知竞争者）
4. `qlmanage -r` 与 `qlmanage -r cache` —— 重建 Quick Look 索引

**四步缺一不可**：少了选举，系统退回内置纯文本预览，表现是「空格显示 Markdown 源码、
等宽字体、右上角写着通过 Spacedown 打开」。2026-11-19 重装时踩过。

命令行侧的自查手段（`pluginkit -m` / `log show` 在沙箱里会报
`unauthorized discovery flag (PKDiscoverAll)`，所以让 App 代跑）：

```bash
defaults write cn.29dev.Spacedown DebugDumpQLLog -bool true   # 打开诊断导出
# 重启 App → 菜单「显示 → 接管…」，报告落到 ~/Desktop/spacedown-ql.txt
defaults delete cn.29dev.Spacedown DebugDumpQLLog             # 用完删掉
```

报告第三、四节看 `+` / `-` 的选举状态，第一节看有没有 `preview file=`。

## 两个「静默失效」的坑

### ① 扩展必须沙箱化，否则系统静默不加载

`QuickLookPreview.appex` 必须带 `com.apple.security.app-sandbox`
（`QuickLookPreview/QuickLookPreview.entitlements`，由 `gen_project.py` 挂到 appex 目标）。
不带的后果不是报错，而是**静默失效**：扩展永远不会被拉起、`os_log` 一行都没有、
系统设置里也看不到它——然后系统退回去用别家扩展。

自查（不用按空格）：

```bash
codesign -d --entitlements - /Applications/Spacedown.app/Contents/PlugIns/QuickLookPreview.appex
```

必须看到 `com.apple.security.app-sandbox = true`。

### ② 构建目录被登记成「第二个扩展」

`xcodebuild` 跑过之后，LaunchServices 里同一个 `pluginIdentifier` 可能出现两条记录
（构建目录 + `/Applications`），系统于是拿不准，**静默退回别家扩展**。

判据：`lsregister -dump | grep -A3 cn.29dev.Spacedown.QuickLookPreview`，同一个 ID 下
只应出现 1 条指向 `QuickLookPreview.appex` 的 `path:`。

修法：打开 `/Applications` 里那份 App，菜单「显示 → 接管 Markdown 空格预览」重跑四步。
**不要**用 `lsregister -u` 去注销哪一份（见上一节的警告）。

## 打包与发布

```bash
scripts/release.sh                                    # 只打包，版本取 MARKETING_VERSION
scripts/release.sh --version 1.1.0                    # 指定版本
scripts/release.sh --version 1.1.0 --publish          # 一条命令发完
scripts/release.sh --version 1.1.0 --skip-build       # 复用已打好的 dmg / zip
scripts/release.sh --version 1.1.0 --publish --notes-file /tmp/notes.md
```

脚本做三件事：Release 全量构建 →（可选）Developer ID 重签 + 公证 → 出 `dmg` / `zip`
（dmg 内含 App、`/Applications` 软链与安装说明）。`--publish` 上传到
**`Czw96/Spacedown`** 的 Release，同时上传 zip 的 Ed25519 签名。

dmg 的精美窗口布局由 `scripts/make_dmg.py` 生成（`pip install dmgbuild pillow`）；
没有这两个依赖时自动回退成普通 `hdiutil` dmg，功能一样，只是没有背景与图标摆位。

### 正式签名（需要 Developer ID）

```bash
xcrun notarytool store-credentials spacedown \
  --apple-id <Apple ID> --team-id <Team ID> --password <App 专用密码>

SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" \
NOTARY_PROFILE=spacedown \
scripts/release.sh --version 1.1.0 --publish
```

不带 `SIGN_IDENTITY` 时产物是 **ad-hoc 签名**：本机可用，别人下载后首次打开被 Gatekeeper 拦。
macOS 15 起「右键 → 打开」已失效，只能走「系统设置 → 隐私与安全性 → 仍要打开」，
或 `xattr -dr com.apple.quarantine /Applications/Spacedown.app`。

## 应用内自动更新（Ed25519 自签）

没有 Developer ID，Apple 不会为更新包背书，所以「这个包确实是我们发的」只能自己保证：
发布时用 **Ed25519 私钥**签 zip，App 里用烘焙的公钥验签（等价于 Sparkle 的 EdDSA）。

```bash
# 首次：生成密钥对（私钥落在仓库外，公钥按提示粘进源码）
swift scripts/sign_update.swift --generate

# 之后每次发布：release.sh 打包后自动签名，产出 Spacedown-<ver>.zip.sig 一起上传
scripts/release.sh --version 1.0.6 --publish
```

- 私钥：`~/.spacedown-signing/update-signing.key`（600）。**丢了只能换新密钥**，
  而老版本里烘焙的是旧公钥——那种情况只能让用户手动下载一次。
- 公钥：`Spacedown/Update/UpdateSigning.swift` 的 `publicKeyBase64`。
- 没有私钥时 `release.sh` 跳过签名（别人 clone 也能打包），这种包**不会**被自动安装，
  用户会看到「请手动下载」。
- 只校 sha256 没意义：那个值也是 GitHub 算的，账号被盗就一起被换。
- 换包由 `Spacedown/Resources/swap.sh` 完成：等进程退出 → ditto 到 `.updating` →
  两次 rename 交换 → 启动成功才删 `.old`，任何一步失败都回滚。

⚠️ 自更新只解决「升级」：首次安装仍是未公证的 ad-hoc 包，会被 Gatekeeper 拦一次。

## 卸载

设置窗（<kbd>⌘</kbd><kbd>,</kbd>）→「卸载 Spacedown…」：彻底删除，不进废纸篓。

- `~/Library/Containers` 受 data vault 保护，`rmdir` / rename 一律 `EPERM`；
- **QL 扩展的沙箱容器删不掉**（containermanagerd 托管），弹窗不承诺这一项；

## 环境注意

| 坑 | 现象 | 处理 |
|---|---|---|
| `xcode-select` 指向 CommandLineTools | 能编，但打包 `.appex` 缺 SDK/签名链路 | `sudo xcode-select -s /Applications/Xcode.app` |
| 沙箱里 `git clone` 走 HTTPS | `Error in the HTTP2 framing layer` | `curl --noproxy '*' -L https://codeload.github.com/<repo>/tar.gz/refs/heads/<branch>` |
| bash 里 `${VAR}` 紧跟全角标点 | `$VAR` 被吞 | 写 `${VAR}` |
