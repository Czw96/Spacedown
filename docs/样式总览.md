## 5. 提示块（GitHub 风格）

> [!NOTE]
> 适合写"补充说明"。左边线条 + 浅色底，标签是「注意」。

> [!TIP]
> 适合写"小技巧"。标签是「提示」。

> [!IMPORTANT]
> 适合写"必须知道的事"。标签是「重要」。

> [!WARNING]
> 适合写"容易出错的地方"。标签是「警告」，左边线更粗。

> [!CAUTION]
> 适合写"会造成损失的操作"。标签是「危险」。

> 说明：`> [!NOTE]` 这类写法不在 GFM 里，是 GitHub 自己的约定。
> Spacedown 在**渲染期**把它转成带 class 的引用块，所以纯 CSS 就能上色，页面仍然零 JS。

## 6. 代码

行内代码：`npm run build`、`defaults write cn.29dev.Spacedown DebugLayout -bool true`。

带语言的代码块：

```swift
/// 渲染期的后处理：给表格套一个横向滚动容器
private static func wrappingTables(_ body: Data) -> Data {
    let open = Data("<table".utf8)
    let wrap = Data(#"<div class="table-wrap">"#.utf8)
    var out = Data()
    out.reserveCapacity(body.count)
    var cursor = body.startIndex
    while let hit = body.range(of: open, in: cursor..<body.endIndex) {
        out.append(body[cursor..<hit.lowerBound])
        out.append(wrap)
        cursor = hit.lowerBound
    }
    out.append(body[cursor...])
    return out
}
```

## 10. 原始 HTML（允许）

<div style="padding:12px 16px;border-radius:8px;background:#f2f2f3;border:1px solid #d9d9d9">
  这一块是**原始 HTML**，不属于 markdown 语法，但 Spacedown 允许它渲染（cmark 的 UNSAFE 选项）。
</div>

危险 scheme 会被中和：<a href="javascript:alert(1)">这个链接点了不会有任何事</a>

> 说明：`javascript:` / `vbscript:` / `data:text/html` 这类 `href`/`src` 会被替换成 `#blocked-…`，
> 并且属性名有边界判断（`data-href=` 不会被误伤）。

## 11. 不支持 / 会原样显示

下面这些写法 **cmark-gfm 不支持**，会当成普通文本显示 —— 放在这里是为了"知道边界在哪"：

- 脚注：[^1]
- 数学：$x^2 + y^2 = c^2$
- 流程图：mermaid / graphviz 代码块（只会当普通代码块显示）
- 定义列表（Markdown Extra 语法）

[^1]: 这行本身会作为普通段落出现。

> 说明：这三样都需要额外的渲染器（KaTeX / Mermaid）和页面 JS，与"离线 + 零 JS + 严格 CSP"冲突，已评估后不做。

## 12. 排版细节

**中英混排**：Spacedown 是一个 macOS 上的 Markdown 速览工具，支持 Apple Silicon。

**长句换行**：这是一段足够长的中文，用来观察在宽窗口下自动换行后的行距与两端留白是否舒服；如果版心铺满整窗，行会变得太长，眼睛回行容易串行，可以在「显示 → 版心宽度」里收窄。

**超长链接**（应当折行而不是撑破版心）：<https://github.com/Czw96/Spacedown/blob/master/docs/%E6%8A%80%E6%9C%AF%E6%96%B9%E6%A1%88.md#%E6%B8%B2%E6%9F%93%E5%86%85%E6%A0%B8>

> 说明：正文使用 `overflow-wrap: break-word`，所以超长 URL 会折行。
